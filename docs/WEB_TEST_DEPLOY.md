## 本地启动

推荐双击：

```text
start.bat
```

如果 3000 端口被占用，可双击：

```text
start-3001.bat
```

也可以在项目目录执行：

```bash
npm start
```

如果使用 PowerShell 手动启动，请先进入项目目录，并在文件名前加 `.\`：

```powershell
cd "C:\Users\lixin11190\Documents\New project\phde-checkin-system"
.\start.bat
```

备用 3001 端口：

```powershell
.\start-3001.bat
```

浏览器访问：

```text
http://localhost:3000
```

或：

```text
http://localhost:3001
```

## 外网测试建议

可以部署到支持 Node.js 的平台，例如 Render、Railway 或普通云服务器。

启动命令：

```bash
npm start
```

平台需要提供可写文件系统，否则 `data/phde-state.json` 可能在服务重启后丢失。测试阶段可以接受；正式使用建议换成 PostgreSQL、MySQL 或 SQLite 持久化数据库。

## 测试方式

员工首次签到时填写姓名、工号、手机号，选择办公地点后点击“上班签到”。工号不存在时，系统会自动创建员工档案；工号已存在时，会校验姓名是否匹配。

填写姓名和工号后，页面会显示签到前确认提示。测试时可重点观察：

- 页面是否呈现低饱和蓝白渐变、半透明毛玻璃卡片、柔和阴影和统一圆角。
- 页面背景是否显示洁净室实验人员高清照片，并且前景表单文字仍清晰可读。
- 顶部 Morimatsu 横版 LOGO 是否融入玻璃标题栏，不应看到明显白色长方形底或矩形阴影。
- 首页标题上方不再显示 `PHDE` 眼标，`员工上班签到` 更靠上，标题、说明和表单间距更紧凑。
- 顶部任务栏是否比上一版更透明，能看到更多背景照片细节。
- 点击顶部“深色/浅色”按钮，确认页面可在浅色和深色模式之间切换。
- 鼠标悬停卡片和按钮时，确认有轻微上浮和阴影变化；如系统开启减少动态效果，动画应明显减弱。
- 首次登记显示“首次登记”。
- 手动地点使用下拉框选择；页面不再显示地点快捷按钮横条，也不再显示“当前状态 / 修改机会 / 数据模式”横向状态卡。
- 定位成功后地图应优先显示 Leaflet 开源地图，底图为白底灰线的浅色地图，可拖拽查看，并可通过缩放按钮、滚轮、双击或触摸手势自由缩放；如果外部地图库加载失败，应退回本地高科技示意地图。
- 当天未签到员工显示“今日未签到”。
- 当天已签到且可修改时显示“今日已签到”和剩余修改机会。
- 今日状态卡中的工号、手机号、时间、地点和自动定位应尽量压缩在一条信息行内；长定位文本可以省略，不应把单个员工卡片撑成多行。
- 在墨西哥当地晚上测试时，已签到记录仍应显示为当天已签到，不应因为 Render 使用 UTC 日期而跨到次日。
- 姓名和工号不匹配时显示“信息不匹配”。
- 首页“签到动态”默认可折叠，展开后显示往日签到记录；当天记录仍显示在今日状态中。
- 登录管理后台后，点击“产品文档”和“技术方案”，确认能在后台查看文档内容。
- 未登录时直接访问 `/docs/PRD.md` 或 `/docs/TECHNICAL_PLAN.md` 应被拒绝。

如果刚同步过 Figma、CSS 样式或 LOGO 图片，浏览器或 Render CDN 可能缓存旧文件。请按 `Ctrl + F5` 强制刷新，确认页面引用的是最新样式版本；Render 部署后也可在 Dashboard 中确认最新 GitHub commit 已经进入 Live 状态。
